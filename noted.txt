split comes from views that do not exist yet, hence 0 and 0.

WHY IT SHOWED 0 INSTEAD OF AN ERROR
-----------------------------------
Every function in src/lib/reporting/queries.ts destructured only `data` and
discarded `error`, so a missing view, a denied grant or a typo all rendered as a
plausible-looking 0. Fixed in this commit: all 18 reporting reads now throw via
`reportingError()`, which surfaces at src/app/[locale]/(app)/error.tsx.

Note that error.tsx renders only `error.digest`, never `error.message`, so the
on-screen panel is generic. The real message is in the dev-server terminal:

  reporting: query on report_room_summary_by_segment failed -- Could not find
  the table 'public.report_room_summary_by_segment' in the schema cache

WHY IT COULD NOT BE APPLIED
---------------------------
Direct Postgres is firewalled on this machine, so `npm run db:push` cannot
reach the database:

  aws-0-ap-southeast-1.pooler.supabase.com:5432  TIMEOUT
  aws-0-ap-southeast-1.pooler.supabase.com:6543  TIMEOUT
  db.<ref>.supabase.co:5432                      ENOTFOUND

This is a network block, not a credential problem — the HTTPS REST API to the
same project works fine.
